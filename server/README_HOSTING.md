# راهنمای انتقال پروژه «رقابت کن، جایزه ببر» به هاست Node.js

این راهنما برای انتقال سرور از محیط Render به یک هاست اشتراکی یا اختصاصی Node.js (مانند VPS) تهیه شده است.

## ۱. پیش‌نیازها
- Node.js نسخه 20 یا بالاتر (توصیه شده: 22.x)
- دسترسی به Terminal/SSH
- نصب بودن PM2 (اختیاری اما توصیه شده برای مدیریت فرآیند)
- پایگاه داده Supabase فعال

## ۲. مراحل نصب و راه‌اندازی

### مرحله ۱: انتقال فایل‌ها
فقط محتویات پوشه `server` را به هاست جدید منتقل کنید. ساختار فایل‌ها باید به صورت زیر باشد:
- `server.js` (فایل اصلی اجرا)
- `package.json`
- `ecosystem.config.js` (تنظیمات PM2)
- پوشه `public/` (شامل فایل‌های استاتیک پنل مدیریت)
- پوشه `rewards-service/` (سرویس جوایز)

### مرحله ۲: نصب وابستگی‌ها
در پوشه اصلی سرور، دستور زیر را اجرا کنید:
```bash
npm install
```

### مرحله ۳: تنظیم متغیرهای محیطی
فایل `.env.example` را کپی کرده و به نام `.env` ذخیره کنید:
```bash
cp .env.example .env
```
سپس مقادیر واقعی را در فایل `.env` وارد کنید. 

**نکات امنیتی بسیار مهم:**
- **ADMIN_KEY:** انتخاب یک کلید بسیار قوی و طولانی الزامی است. در صورت عدم تنظیم این کلید، پنل مدیریت غیرقابل دسترس خواهد بود. هیچ کلید پیش‌فرضی در کد وجود ندارد.
- **DATABASE_URL:** حتماً از رشته اتصال **Connection Pooler** در Supabase (پورت 6543) استفاده کنید تا با محدودیت تعداد اتصال مواجه نشوید.

### مرحله ۴: ایجاد پوشه‌های لازم
پوشه‌های لاگ و آپلود را ایجاد کنید (این پوشه‌ها برای پایداری اطلاعات ضروری هستند):
```bash
mkdir -p logs
mkdir -p public/uploads
```

### مرحله ۵: اجرا و پایداری با PM2
بهترین روش برای اجرای پایدار برنامه استفاده از PM2 است. تنظیمات در فایل `ecosystem.config.js` به گونه‌ای انجام شده که کل پروژه (شامل سرویس جوایز) در یک فرآیند واحد اجرا شود:
```bash
pm2 start ecosystem.config.js
pm2 save
```

**اجرای خودکار پس از ریستارت سرور (Auto-restart):**
برای اینکه برنامه پس از ریستارت شدن خودِ سیستم (OS Restart) به صورت خودکار اجرا شود، دستور زیر را بزنید:
```bash
pm2 startup
```
پس از اجرای این دستور، یک خط کد به شما نمایش داده می‌شود که باید آن را کپی کرده و با دسترسی `sudo` اجرا کنید. در نهایت دوباره دستور `pm2 save` را بزنید.

## ۳. نکات نگهداری و فایل‌های آپلودی

### پایداری تصاویر
تصاویر و بنرهای آپلود شده ابتدا در پوشه `public/uploads` ذخیره می‌شوند. اگر هاست شما دارای فضای ذخیره‌سازی دائمی (Persistent Disk) است، فایل‌ها امن هستند. در غیر این صورت، حتماً متغیرهای `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را تنظیم کنید تا سیستم به صورت خودکار تصاویر را در **Supabase Storage** (باکت `gift-banners`) ذخیره کند.

### بکاپ‌گیری
- **دیتابیس:** از بخش Database -> Backups در پنل Supabase.
- **فایل‌های محلی:** به صورت دوره‌ای از پوشه `public/uploads` کپی تهیه کنید.

### مشاهده وضعیت و لاگ‌ها
```bash
pm2 status               # مشاهده وضعیت کلی
pm2 logs reqabat-backend # مشاهده لاگ‌های زنده (خروجی و خطاها)
pm2 monit                # پایش مصرف RAM و CPU
```

## ۴. عیب‌یابی (Troubleshooting)
- **خطای اتصال دیتابیس:** وضعیت اینترنت هاست و صحت `DATABASE_URL` را بررسی کنید.
- **عدم دسترسی به پنل مدیریت:** مطمئن شوید `ADMIN_KEY` در فایل `.env` دقیقاً با مقداری که وارد می‌کنید یکسان است.
- **خطای پورت:** اگر پورت 3000 توسط برنامه دیگری اشغال شده، مقدار `PORT` را در `.env` تغییر دهید.
- **پوشه Logs:** اگر فایل‌های لاگ ساخته نشدند، دسترسی نوشتن (Permission) در پوشه پروژه را بررسی کنید.
