# راهنمای انتقال پروژه «رقابت کن، جایزه ببر» به هاست Node.js

این راهنما برای انتقال سرور از محیط Render به یک هاست اشتراکی یا اختصاصی Node.js (مانند VPS) تهیه شده است.

## ۱. پیش‌نیازها
- Node.js نسخه 20 یا بالاتر (توصیه شده: 22.x)
- دسترسی به Terminal/SSH
- نصب بودن PM2 (اختیاری اما توصیه شده برای مدیریت فرآیند)
- پایگاه داده Supabase فعال

## ۲. مراحل نصب و راه‌اندازی

### مرحله ۱: انتقال فایل‌ها
فقط محتویات پوشه `server` را به هاست جدید منتقل کنید. ساختار فایل‌ها باید به صورت زیر باشد:
- `server.js` (فایل اصلی اجرا)
- `package.json`
- `ecosystem.config.js` (تنظیمات PM2)
- پوشه `public/` (شامل فایل‌های استاتیک پنل مدیریت)
- پوشه `rewards-service/` (سرویس جوایز)

### مرحله ۲: نصب وابستگی‌ها
در پوشه اصلی سرور، دستور زیر را اجرا کنید:
```bash
npm install
```

### مرحله ۳: تنظیم متغیرهای محیطی
فایل `.env.example` را کپی کرده و به نام `.env` ذخیره کنید:
```bash
cp .env.example .env
```
سپس مقادیر واقعی را در فایل `.env` وارد کنید. **نکته مهم:** حتماً از رشته اتصال **Connection Pooler** در Supabase (پورت 6543) برای `DATABASE_URL` استفاده کنید.

### مرحله ۴: ایجاد پوشه‌های لازم
پوشه‌های لاگ و آپلود را ایجاد کنید:
```bash
mkdir -p logs
mkdir -p public/uploads
```

### مرحله ۵: اجرا با PM2
بهترین روش برای اجرای پایدار برنامه استفاده از PM2 است:
```bash
pm2 start ecosystem.config.js
pm2 save
```
برای اطمینان از اجرای خودکار پس از ریستارت سرور:
```bash
pm2 startup
```

## ۳. نکات امنیتی و نگهداری

### پایداری فایل‌ها
تصاویر و بنرهای آپلود شده در پوشه `public/uploads` ذخیره می‌شوند. در صورتی که هاست شما فضای دائمی ندارد، حتماً متغیرهای `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را تنظیم کنید تا فایل‌ها در Supabase Storage ذخیره شوند.

### بکاپ‌گیری
- **دیتابیس:** بکاپ‌گیری منظم از طریق پنل Supabase (بخش Database -> Backups) انجام شود.
- **فایل‌ها:** در صورت عدم استفاده از Cloud Storage، از پوشه `public/uploads` به صورت دوره‌ای نسخه پشتیبان تهیه کنید.

### پایش (Monitoring)
برای مشاهده لاگ‌های برنامه:
```bash
pm2 logs reqabat-backend
```
برای مشاهده وضعیت مصرف منابع:
```bash
pm2 monit
```

## ۴. عیب‌یابی (Troubleshooting)
- اگر سرور اجرا نشد، ابتدا `DATABASE_URL` را چک کنید.
- مطمئن شوید پورت تعیین شده (3000) در فایروال هاست باز است.
- در صورت بروز خطای `EADDRINUSE` فرآیند قبلی را با `pm2 stop all` متوقف کنید.
