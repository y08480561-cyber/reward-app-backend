# راهنمای جامع انتقال پروژه «رقابت کن، جایزه ببر» به هاست اشتراکی و سرور Node.js (نسخه ۲۲)

این سند راهنمای کامل گام‌به‌گام برای انتقال، نصب، پیکربندی، ایمن‌سازی و اجرای پایدار سرور و پنل مدیریت بر روی انواع هاست‌های اشتراکی Node.js (سی‌پنل، کلودلینوکس، دایرکت‌ادمین) و سرورهای مجازی (VPS / Cloud) می‌باشد.

---

## ۱. پیش‌نیازها و مشخصات فنی
- **نسخه Node.js:** نسخه 20 الی 22 (پیشنهادی: Node.js 22.x LTS)
- **پایگاه داده:** پایگاه داده ابری Supabase PostgreSQL (با Transaction Pooler پورت 6543)
- **فضای ذخیره‌سازی ابری:** Supabase Storage (باکت عمومی `gift-banners`)
- **بدون وابستگی به ابزارهای ساخت C++:** تمام پکیج‌های پروژه Pure JavaScript هستند و نیازی به کامپایلر ندارد.

---

## ۲. فایل‌های مورد نیاز جهت انتقال
تنها کافی است محتویات پوشه `server` را آپلود نمایید. نیازی به آپلود پوشه `node_modules` نیست.

فایل‌های ضروری:
- `server.js` (نقطه ورودی و فایل اصلی اجرای سرور)
- `package.json` (تعریف بسته‌ها و اسکریپت start)
- `ecosystem.config.js` (پیکربندی PM2 برای هاست‌هایی که از PM2 پشتیبانی می‌کنند)
- `public/` (پوشه رابط کاربری پنل مدیریت و صفحه فهرست کاربران)
- `rewards-service/` (میکروسرویس یکپارچه جوایز)
- `.env.example` (الگوی متغیرهای محیطی)

## ۳. روش‌های اجرا در محیط‌های مختلف هاستینگ

### روش الف: هاست اشتراکی سی‌پنل (cPanel / Setup Node.js App / Phusion Passenger)
بسیاری از هاست‌های اشتراکی از ابزار "Setup Node.js App" استفاده می‌کنند و دستور `pm2` در آن‌ها فعال نیست:

1. وارد **cPanel** شده و گزینه **Setup Node.js App** را باز کنید.
2. روی دکمه **Create Application** کلیک کنید:
   - **Node.js version:** نسخه `22.x` (یا `20.x`) را انتخاب کنید.
   - **Application mode:** روی `Production` قرار دهید.
   - **Application root:** نام پوشه آپلود شده پروژه (مثلاً `reqabat-server` یا `public_html/api`).
   - **Application startup file:** دقیقاً عبارت `server.js` را وارد کنید.
3. در بخش **Environment variables**، متغیرهای الزامی را وارد کنید (یا فایل `.env` را در ریشه برنامه قرار دهید).
4. روی **Run NPM Install** کلیک کنید تا وابستگی‌ها دانلود و نصب شوند.
5. روی دکمه **Restart** یا **Start Application** کلیک نمایید.

**تنظیم هدایت ترافیک در `.htaccess` (در صورت نیاز به Reverse Proxy):**
```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteRule ^$ http://127.0.0.1:3000/ [P,L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^(.*)$ http://127.0.0.1:3000/$1 [P,L]
</IfModule>
```

---

### روش ب: اجرای پایدار با PM2 (در هاست‌های دارای ترمینال یا سرورهای VPS)
اگر به ترمینال SSH و دستور `pm2` دسترسی دارید:

1. وارد پوشه سرور شوید و وابستگی‌ها را نصب کنید:
   ```bash
   npm install --production
   ```
2. فایل `.env` را از روی `.env.example` بسازید و مقادیر واقعی را وارد کنید:
   ```bash
   cp .env.example .env
   nano .env
   ```
3. پوشه لاگ‌ها را ایجاد کنید:
   ```bash
   mkdir -p logs
   ```
4. برنامه را از طریق فایل تنظیمات PM2 روشن کنید:
   ```bash
   pm2 start ecosystem.config.js
   pm2 save
   ```
5. برای راه‌اندازی مجدد خودکار هنگام ری‌استارت سیستم‌عامل سرور:
   ```bash
   pm2 startup
   ```

---

### روش ج: اجرای مستقیم (Standalone Node.js / Docker / Systemd)
```bash
npm install --production
npm start
```
سرور به شکل پیش‌فرض روی پورت تعریف‌شده در متغیر `PORT` (پیش‌فرض 3000) به تمام آدرس‌ها (`0.0.0.0`) متصل می‌شود.

## ۴. متغیرهای محیطی الزامی (`.env`)

| نام متغیر | الزامی؟ | توضیحات |
|-----------|---------|---------|
| `PORT` | خیر | پورت گوش‌دادن سرور (پیش‌فرض: `3000`) |
| `NODE_ENV` | بله | حتماً مقدار `production` تنظیم شود |
| `DATABASE_URL` | بله | رشته اتصال Supabase Transaction Pooler (پورت 6543) |
| `ADMIN_KEY` | بله | کلید احراز هویت پنل و APIهای مدیریت (طولانی و تصادفی) |
| `SUPABASE_URL` | بله | آدرس پروژه در Supabase جهت آپلود بنرها در استوریج |
| `SUPABASE_SERVICE_ROLE_KEY` | بله | کلید سرویس امنیتی Supabase جهت مدیریت باکت `gift-banners` |
| `AUTH_PIN` | اختیاری | پین ورود کاربران در صورت تمایل به محدودسازی ورود مستقیم |
| `TAPSELL_APP_KEY` | اختیاری | کلید تبلیغاتی تپسل جهت گزارش‌های مدیریتی |
| `TAPSELL_ZONE_ID` | اختیاری | شناسه زون جایزه‌دار تپسل |

## ۵. امنیت و نگهداری

### الف) اتصال امن SSL / HTTPS
- در هاست اشتراکی، از طریق ابزار **SSL/TLS Status** در سی‌پنل گواهی رایگان Let's Encrypt یا AutoSSL را فعال کنید.
- هیچ درخواستی نباید روی پروتکل غیرامن HTTP ارسال شود.

### ب) محافظت از اطلاعات محرمانه
- هیچ‌گاه فایل `.env` حاوی کلیدهای واقعی را در مخزن عمومی Git قرار ندهید.
- کلید `ADMIN_KEY` تنها از طریق هدر `x-admin-key` یا `Authorization: Bearer <KEY>` ارسال می‌شود و ارسال آن در Query String منسوخ و مسدود است.

### ج) پشتیبان‌گیری (Backup)
- **پایگاه داده PostgreSQL:** از بخش Database -> Backups در داشبورد Supabase پشتیبان‌گیری روزانه فعال است. همچنین می‌توانید با ابزار `pg_dump` خروجی SQL تهیه نمایید.
- **بنرهای ذخیره‌شده:** بنرها به طور مستقیم در باکت `gift-banners` در Supabase Storage نگهداری می‌شوند و با ریستارت یا تغییر هاست از بین نخواهند رفت.

### د) بررسی لاگ‌ها و عیب‌یابی
- **در هاست سی‌پنل:** به فایل‌های `stderr.log` یا تب View Logs در بخش Setup Node.js App مراجعه نمایید.
- **در PM2:** با دستور `pm2 logs reqabat-backend` لاگ‌های زنده را مشاهده کنید.
- **بررسی سلامت دیتابیس:** در صورت خطای اتصال به دیتابیس، بررسی نمایید که آیا از آدرس Transaction Pooler پورت 6543 استفاده شده است یا خیر (هاست‌های اشتراکی عموماً فاقد اتصال IPv6 هستند و اتصال مستقیم به پورت 5432 با خطا مواجه می‌شود).
